非标钣金工单系统上线教学

适用于当前版本：网页后台 + 电视看板 + 微信小程序扫码报工。

编写日期：2026-06-03。正式上线前，请以微信公众平台、云服务商、工信部备案系统的实际页面为准。

上线前你要先理解的事

本系统现在已经具备第一版上线需要的核心链路：后台建订单、选择工艺路线、派工、生成工序二维码、小程序扫码报工、上传异常图片、电视看板查看进度。

上线不是简单把本地文件复制出去，而是要让系统具备三个正式条件：公网 HTTPS 域名、稳定运行的后端服务、微信小程序合法域名和扫码规则配置。

第一部分：前 4 个步骤详细操作

1申请并准备微信小程序账号

目标：拿到小程序 AppID，并具备上传体验版、提交审核、发布小程序的权限。

1.1 准备资料

  • 营业执照：建议用公司或个体工商户主体，不建议用个人主体。
  • 法人或管理员身份证、手机号、邮箱。
  • 公司简称、系统名称、logo。名称可先用“宁波未来机械工单”或类似名称。
  • 管理员微信号：后面登录公众平台、扫码确认、上传审核都会用到。
  • 隐私政策需要的信息：系统会收集手机号、姓名、报工数据、现场图片。

1.2 注册入口

  1. 打开 微信公众平台。
  2. 点击“立即注册”。
  3. 选择“小程序”。
  4. 用一个没有注册过公众号/小程序的邮箱注册。
  5. 按页面要求完成主体信息填写和管理员绑定。

1.3 注册完成后要记录的信息

信息 在哪里看 用途
AppID 微信公众平台 -> 开发管理 -> 开发设置 微信开发者工具上传小程序时使用
管理员微信 注册时绑定 扫码登录、体验版预览、审核发布
小程序名称 设置 -> 基本设置 用户在微信里看到的名称

1.4 添加开发成员

  1. 进入微信公众平台。
  2. 找到“成员管理”。
  3. 把需要开发或上传代码的微信号加入开发成员。
  4. 如果以后找外部技术人员上线，也只给开发权限，不要随便给管理员权限。
注意：如果你要让工人长期稳定扫码报工，小程序必须正式发布。体验版适合测试，不适合全厂正式使用。

2准备云服务器或托管云服务

目标：让现在本地的 Node.js 系统在公网上 24 小时运行，老板出差、工人手机、小程序、电视看板都能访问。

2.1 第一版推荐方案

为了尽快上线，建议先用“云服务器 + Node.js + Nginx + HTTPS”。后续订单量变大，再升级数据库、对象存储和云托管。

项目 建议配置 说明
服务器 腾讯云、阿里云、华为云均可 尽量选中国大陆地域，访问稳定，但大陆服务器通常需要备案域名。
系统 Ubuntu 22.04 LTS 或 Windows Server 如果你不熟服务器，Windows 更直观；如果找技术人员部署，Ubuntu 更常见。
配置 2 核 4G、50G 硬盘起步 第一版工厂内部使用足够。图片多时要加硬盘或对象存储。
带宽 3M 起步，建议 5M 电视看板和图片上传会消耗带宽。
安全组 开放 80、443、22 或远程桌面端口 80/443 给网页和小程序访问；22/远程桌面给维护人员登录。

2.2 云服务器购买时怎么选

  1. 进入云服务商控制台，找到“云服务器/CVM/ECS/轻量应用服务器”。
  2. 地域选择离工厂近的地区，例如华东、上海、杭州、宁波周边可选华东区域。
  3. 镜像选择 Ubuntu 22.04 LTS，或者你熟悉 Windows 就选 Windows Server。
  4. 规格选择 2 核 4G 起步。
  5. 公网 IP 必须勾选。
  6. 安全组开放 HTTP 80、HTTPS 443、SSH 22。Windows 则还要开放远程桌面端口。

2.3 第一版数据风险说明

当前系统用 data/db.json 存数据，适合第一版试运行和小规模使用。正式长期使用时，建议后续升级到 MySQL、PostgreSQL 或云数据库。

上线第一天就要建立备份习惯：每天备份 data/db.json 和 public/uploads。

3准备域名、备案和 HTTPS 证书

目标：让系统拥有正式访问地址，例如 https://work.nbwlmachine.com。微信小程序正式请求后端接口时，必须配置合法域名，并且建议使用 HTTPS。

3.1 域名建议

建议用公司主域名的子域名，例如：

work.nbwlmachine.com
mes.nbwlmachine.com
gongdan.nbwlmachine.com

3.2 域名购买

  1. 在腾讯云、阿里云、华为云等平台购买域名。
  2. 完成域名实名认证。
  3. 如果公司已有域名，可以直接新增一个子域名，不需要重新买。

3.3 备案说明

  • 如果服务器在中国大陆，域名通常需要做 ICP 备案。
  • 备案一般需要营业执照、法人信息、网站负责人信息、手机号、人脸核验等。
  • 备案时间不是写代码能加速的，通常要预留数天到数周。
  • 如果急着内部测试，可以先用云服务商临时域名或服务器 IP 做本地/体验版测试，但正式小程序建议用备案后的 HTTPS 域名。

3.4 配置 DNS

备案和服务器准备好后，在域名解析里新增 A 记录：

类型 主机记录 记录值
A work 你的服务器公网 IP

配置后，访问地址就是 work.你的域名.com。

3.5 配置 HTTPS 证书

  1. 在云服务商申请免费 SSL 证书，绑定你的子域名。
  2. 证书签发后，下载或一键部署到 Nginx。
  3. 确认浏览器访问 https://你的域名 没有“不安全”提示。
重点：二维码扫码报工的正式地址依赖 QR_BASE_URL。上线后必须设置成你的 HTTPS 域名，不能是 localhost。

4上传项目到服务器

目标：把当前文件夹里的系统代码放到云服务器，并能在服务器上启动。

4.1 上传前先整理本地文件

当前项目文件夹是：

D:\codex内容\copy黑湖小工单

上传时需要包含这些核心内容：

  • server.js
  • package.json
  • public 文件夹
  • miniprogram 文件夹
  • data 文件夹，首次上线可以带上；后续更新不要随便覆盖线上数据。
  • cloud、docs 可一起上传，方便维护。

可以不上传这些运行日志：

server.out.log
server.err.log

4.2 方式 A：用远程桌面或服务器面板上传

  1. 把 copy黑湖小工单 文件夹压缩成 zip。
  2. 登录服务器远程桌面，或打开宝塔/云服务器文件管理器。
  3. 上传 zip 到服务器。
  4. 解压到例如 /www/work-order 或 C:\work-order。
  5. 进入解压后的目录，确认能看到 server.js。

4.3 方式 B：用命令上传到 Linux 服务器

在你电脑 PowerShell 里执行，示例：

scp -r "D:\codex内容\copy黑湖小工单" root@你的服务器IP:/www/work-order

如果服务器禁止 root 登录，就把 root 换成云服务器创建的用户名。

4.4 服务器安装 Node.js

Linux 服务器示例：

node -v
npm -v

如果提示找不到命令，需要安装 Node.js。建议使用 Node.js 20 LTS 或更新的 LTS 版本。

4.5 首次启动测试

进入项目目录：

cd /www/work-order
npm start

如果看到类似 系统已启动 或没有报错，再在浏览器访问：

http://服务器公网IP:3000

能看到登录页，说明代码已经跑起来了。

重要：这一步只是临时测试。正式给小程序用，必须继续配置 HTTPS、反向代理、合法域名、扫码规则。

第二部分：后续上线步骤简表

5. 设置线上环境变量

PORT=3000
QR_BASE_URL=https://你的正式域名

QR_BASE_URL 决定后台生成二维码时写入哪个正式扫码地址。

6. 配置 Nginx 和 HTTPS

把 https://你的域名 转发到本机 3000 端口。

7. 设置后台服务常驻运行

Linux 可用 pm2 或 systemd，Windows 可用计划任务或服务管理工具。目标是服务器重启后系统自动启动。

8. 微信公众平台配置 request 合法域名

进入微信公众平台 -> 开发管理 -> 开发设置，把你的 HTTPS 域名加入 request 合法域名。

9. 微信公众平台配置普通二维码跳转小程序

配置二维码规则：

https://你的正式域名/scan.html

目标页面：

pages/report/report

10. 修改小程序接口地址

打开：

miniprogram/utils/config.js

改成：

module.exports = {
  apiBaseUrl: "https://你的正式域名",
  cloudEnvId: "请填写微信云开发环境 ID"
};

11. 微信开发者工具上传体验版

  1. 打开微信开发者工具。
  2. 导入 miniprogram 文件夹。
  3. 填写小程序 AppID。
  4. 编译、预览、真机测试。
  5. 上传体验版。

12. 真机测试

  • 老板账号能看移动看板。
  • 主管能新建订单、派工、调整工序。
  • 工人能登录小程序。
  • 后台每道工序能打开二维码。
  • 微信扫码能进入对应工序报工页。
  • 提交报工后，电视看板能刷新显示完成时间和人员。
  • 异常图片能上传和查看。

13. 提交审核并发布

体验版测试通过后，在微信公众平台提交审核。审核通过后点击发布。

第三部分：以后怎么更新线上软件

每次更新前

  1. 先备份线上 data/db.json。
  2. 备份线上 public/uploads。
  3. 记录当前线上版本的压缩包。

只更新网页后台/后端

  1. 上传新的 server.js、public、相关配置文件。
  2. 不要覆盖线上 data/db.json，除非你明确要导入新数据。
  3. 重启 Node 服务。
  4. 测试登录、订单、派工、二维码、报工、电视看板。

更新小程序

  1. 修改 miniprogram 代码。
  2. 微信开发者工具编译并真机测试。
  3. 上传新版本。
  4. 提交微信审核。
  5. 审核通过后发布。

回滚方法

如果更新后出问题，把上一次备份的代码包恢复回服务器，再恢复当时的 data/db.json，然后重启服务。

第四部分：上线前最终检查表

  • 小程序账号已注册，AppID 已记录。
  • 服务器公网 IP 可访问。
  • 域名已解析到服务器。
  • HTTPS 证书正常，浏览器无不安全提示。
  • QR_BASE_URL 已设置成 HTTPS 正式域名。
  • 微信 request 合法域名已配置。
  • 普通二维码跳小程序规则已配置。
  • 小程序 apiBaseUrl 已改成正式域名。
  • 后台能新增订单并派工。
  • 每道工序能打开二维码。
  • 工人扫码能进入对应工序报工。
  • 电视看板能显示报工时间、人员、交期颜色。
  • 每天自动或手动备份数据。
