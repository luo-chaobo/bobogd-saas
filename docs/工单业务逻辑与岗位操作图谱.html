01 / 系统总览

三类界面，共用一条生产数据链

后台负责建单、派工和管理；小程序负责现场执行与报工；电视大屏负责公开展示进度、负荷和风险。所有动作最终沉淀到同一张工单及其工艺路线中。

后台 Web

客户资料、订单工单、工艺路线、派工、异常返工、历史查询、报表与基础设置。

微信小程序

我的任务、扫码开始、报工、质检、异常处理、图纸预览与手机生产看板。

电视生产看板

生产概况、延期与加急风险、工序负荷、报工趋势和活跃加工工单。

02 / 生产主流程

从订单录入到归档

订单保存后同步生成工单与工艺路线。工序完成、异常或返工会自动回写工单状态与看板，不需要重复登记。

01订单录入客户、产品、数量、交期、优先级、图纸与工序。
02自动建工单生成工单号，并按所选工序建立路线。
03派工排期指定人员或按岗位开放，设置计划开始日与结束日。
04开始加工员工在任务页点击开始，或扫码确认开始。
05扫码报工提交完成、返工、备注、现场图片及异常信息。
06质检/异常合格完成；不合格进入报废、让步接收或返工闭环。
07完成归档全部工序完成，工单从活跃看板转入历史查询。

03 / 工序控制

派工决定权限，报工驱动状态

工序状态流转

待开始
→
进行中
→
暂停
→
已完成

进行中可暂停，暂停后可继续；完成数量达到计划数量自动完成。任一异常会使对应工序进入异常，解决后按完成数量恢复进行中或已完成。

权限与校验

  • 1工序已指定员工时，仅该员工及管理角色可操作。
  • 2未指定员工时，按工序所属岗位开放；普通员工不能跨岗位报工。
  • 3待开始必须先开始；暂停状态不可报工；已完成不可再次报工。
  • 4本次完成数量大于 0，累计数量不得超过计划数量；返工数量不得超过本次完成数量。

04 / 质检与返工

质检是正式工序，异常必须闭环

质检前一道生产工序完成且有可送检数量时，质检才可报工。不合格不能只留备注，必须形成对应的异常和处置记录。

送检

送检数量与检验数量均大于 0，且两者必须相等。

判定

合格数量与不合格数量之和必须等于检验数量。

不合格处置

选择让步接收、报废或返工；填写问题工序和问题说明。

闭环复检

返工时在质检前插入返工工序，返工完成后进入复检和异常解决。

正常完成

全部合格的数量计入质检完成；达到计划数量后，质检工序自动完成。

异常联动

生产报工填写异常、质检发现不合格或管理手工登记，都会创建异常记录；主管、质检、老板、管理员可填写处理说明并解决。

让车间先看到最需要处理的工单

电视大屏、小程序横屏看板使用同一套业务语义；手机竖屏看板保留工单卡片和分段工序进度，便于快速查看。

活跃工单范围

只展示未完成工单；所有工序完成后自动退出活跃列表，转入历史查询。

工单排序

延期单优先，其次为 48 小时内加急单，再按交期由近到远排列；普通单遵循交期顺序。

工序节点

横向椭圆节点显示计划时间区间；节点下方显示工序名；最近报工显示报工日与报工人。晚于计划结束日时，报工日期标红。

未解决的质检异常使质检节点紫色泛光、问题工序文字紫色高亮；一页显示不下时按后台设置自动翻页轮播。

06 / 岗位操作地图

每个岗位只做职责范围内的事

系统将管理、排产、现场生产、质检和基础维护分开。工人看到的是自己的未完成任务，管理角色负责跨工序协调与异常闭环。

老板

全局监控与决策

  • 查看生产中工单、延期风险和异常数量。
  • 查看手机横屏大屏、电视看板和异常列表。
  • 必要时参与异常处理结果确认。

重点：哪些订单在做、快延期、存在异常。

生产主管

建单、排产与异常协调

  • 维护客户，创建订单并选择实际工艺路线。
  • 给每道工序派人、设置计划时间、增删未报工工序。
  • 处理异常，查看生产总览和基础报表。

重点：工单准确、派工清楚、异常及时闭环。

办公室/跟单

订单信息与交期沟通

  • 维护客户资料，录入订单、产品、图号、数量与交期。
  • 查询当前工序和生产状态。
  • 导出报工 CSV 或完整数据用于统计。

重点：订单准确、交期清楚、对外答复有依据。

车间工人

执行指定工序与及时报工

  • 从“我的任务”找到被派给自己的工序。
  • 开始、暂停、继续后提交完成件数与返工数量。
  • 有异常时填写类型、说明和现场图片。

重点：数量真实，完成及时报工，问题及时上报。

质检

检验、处置与质量异常

  • 在可送检数量满足条件时进行质检报工。
  • 录入合格、不合格与处置方式。
  • 选择问题工序、返工工序，提交质量异常。

重点：质量问题必须落到具体工单和工序。

管理员

账号、角色与基础资料

  • 维护员工、岗位角色、标准工序和看板设置。
  • 停用不再使用的工序，保证新订单不能误选。
  • 检查账号与权限是否匹配实际岗位。

重点：账号、权限和基础资料正确可用。
