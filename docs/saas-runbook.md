# SaaS 本地运行与上线前置

## 存储与租户路由

启用 SaaS 模式后，平台目录（公司、授权、会话、审计和租户库分配元数据）由 `SAAS_CATALOG_MYSQL_*` 连接独立数据库；业务状态路由到每租户独立 MySQL 数据库。预置租户（未来机械）的连接由 `SAAS_TENANT_DATABASES_JSON` 提供；平台创建的新公司由服务端自动分配独立数据库和最小权限应用账号，路由元数据保存在平台目录，应用账号密码使用 `SAAS_TENANT_CREDENTIAL_SECRET` 派生，不保存明文。每个应用账号仅允许访问本租户库。SaaS 业务状态在各自库的 `app_state.name='main'` 保存；不会用 `saas_tenants.state_key` 将多个公司映射进共享业务库。

请求租户来自已校验的会话。平台上下文不能读取业务库；只有完成数据库预配并登记路由的公司才可访问；预配或目录事务失败时会尝试删除本次新建的数据库和账号，不回退到旧 `MYSQL_*` 库或其他租户。未来机械生产库不得配置为 SaaS 租户库；迁移前要将经确认的备份快照导入新的独立租户库，并执行记录、附件和恢复核对。

本地双库初始化见 [local-mysql-startup.md](local-mysql-startup.md) 和 `local-saas-databases.sql`。本地启动需提供 `SAAS_TENANT_PROVISIONER_USER/PASSWORD`（有创建/删除数据库、创建用户及按库授权能力的专用运维账号）和至少 32 字节的 `SAAS_TENANT_CREDENTIAL_SECRET`。生产环境通过受控密钥管理提供相同配置；所有应用实例必须共享同一个凭据派生密钥，并能读取同一个平台目录。不要将预配管理员密码或派生密钥放进代码、数据库明文或前端。预配账号应限制在专用 MySQL 实例/网络，仅授予公司开户所需权限。

## 外部平台订单与回传

外部接口使用 `SAAS_TENANT_INTEGRATIONS_JSON` 服务端映射。每个租户可单独配置 `inboundSecret`、`webhookUrl`、`webhookSecret`；入站请求用 HMAC 签名匹配唯一租户密钥，调用方不能通过租户 ID、公司标识或数据库名选择业务库。不同租户的入站密钥必须唯一且至少 32 个字符。平台回调地址必须为 HTTPS，回调密钥至少 32 个字符。示例仅展示结构，不可直接用于部署：

```json
{
  "future-machinery": {
    "inboundSecret": "REPLACE_WITH_UNIQUE_32_CHAR_SECRET",
    "webhookUrl": "https://platform.example.invalid/api/webhooks/bobo",
    "webhookSecret": "REPLACE_WITH_UNIQUE_32_CHAR_SECRET"
  }
}
```

订单接入路由为 `GET /api/external/health`、`POST /api/external/work-orders`；平台订单由公司主管通过 `POST /api/platform-orders/confirm` 确认工序，`POST /api/platform-orders/sync-processes` 可请求重发进度。进度、发货和配送完成事件先写入对应租户库，再由回调任务按退避策略发送。回调接收方必须按 `eventId` 幂等去重：若网络已接收事件但服务端在记录送达前中断，后续会重试。未配置租户回调时事件保留在队列中，不能视为平台已收到。

SaaS 业务请求按租户在本地排队，并在该租户 MySQL 连接上持有 `GET_LOCK`，避免多个服务进程并发读改写同一个 `app_state.main` JSON 状态。平台回调另有每租户 MySQL 锁，避免多实例重复并行发送。MySQL 必须支持命名锁；锁等待超过 15 秒会失败关闭。委外任务横跨公司库和 SaaS 目录库，失败补偿不等于跨库原子事务，正式开放前仍需对异常中断做专门恢复演练。

## 首期页面和能力

平台后台位于 `/platform-admin.html`，支持公司创建/停用、首位公司管理员创建和年费/收款状态管理。公司内有权限的管理员可从生产后台进入 `/outsourcing.html`，建立委外关系、委派订单/工序/数量，查看委外工单、进度、异常、图纸副本和交付状态。

公司上传文件写入 `public/uploads/tenants/<tenantId>/`。SaaS 下载由应用按登录租户和业务记录文件引用校验；反向代理不能绕过应用直接暴露 `/uploads/` 静态目录。

## Web 后台与微信小程序

Web、小程序使用相同的租户登录会话。小程序登录后的 `/api/login` 和续期读取 `/api/me` 返回相同的模块键集合及模块目录；目录中包含 API 前缀，客户端据此隐藏无套餐入口并给出明确提示。主租户模块名为“外协监管”，伙伴租户模块名为“委派任务”，模块键和接口归属不变。每个请求仍携带当前租户登录会话，服务端继续校验租户库、套餐模块、岗位权限和委派关系，客户端缓存不授予访问权。

小程序移动流程按同一模块键接入：生产总览 `dashboard`，车间任务/扫码报工 `dispatch`，异常质检 `quality`，配送 `orders`，委派任务 `outsourcing`。主租户和外协租户共用委派状态接口：外协接单方处理收到的任务，委托方查看进度并验收；关系权限决定可见的进度、异常和操作。接受后的生产报工继续写入该外协租户自己的数据库，主租户通过外协投影监管，不直接共享业务库。

微信小程序仅适配移动生产流程，不承诺把每个 Web 管理页复制成小程序页面；套餐模块与服务端 API 仍共享同一个目录。当前尚需在微信开发者工具及测试租户库验证登录切换、模块显隐、状态同步、不同岗位和关系权限，再考虑提交小程序版本。

## 保留主程序功能的验收范围

商业化副本包含原有 Web 页面、服务端 API、电视看板及本地小程序副本，但“代码存在”不代表“功能已在 SaaS 下验证”。验收至少覆盖：登录与角色、员工/岗位、客户、订单/工单、工艺路线/派工、车间任务/扫码报工、质检/返工、异常、图纸/附件、生产总览、电视/移动看板、历史、报表/导出、客户反馈、操作日志、设置、交付状态及外部同步。微信小程序必须对用户指定的同步只读源逐页比较并实机回归。

## 当前未完成项

- 功能基线中的服务端路由名已与源版对齐；仍需全量权限、附件、搜索、导出和代理路径越权审查，以及 MySQL 跨租户负向测试。
- 自动预配的新租户数据库流程已接入代码；仍需在本地 MySQL 完成真实创建/登录/重启验证，并在生产环境确认专用预配账号权限、网络来源、密钥管理和多实例一致性。
- 宁波未来机械生产快照迁移、迁移前后数据核对、MySQL 集成联调、恢复演练、生产部署和微信小程序实机发布。
- 本轮功能基线尚需补充经源版本可核对的逐页/接口映射；原同步小程序工作树有未提交状态，不能把它作为干净发布基线。

本轮只改本地 SaaS 副本；未连接或修改生产 MySQL、线上服务、微信发布版本或指定同步小程序目录。
