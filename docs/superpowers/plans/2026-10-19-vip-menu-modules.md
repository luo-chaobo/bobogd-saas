# VIP 主菜单模块化与外协监管实施计划

> **执行约束：** 仅修改 `D:\WMR\lcb\未来网站改造\bobo-saas-commercial`。`bobo-platform-delivery-worktree` 仅作只读功能基线；不得读写生产 MySQL、线上服务或微信小程序，不做部署。SaaS 副本没有 Git 元数据，不创建提交；完成后逐文件核对变更。

**目标：** 为现有主菜单建立稳定、统一的 VIP 模块目录，保证宁波未来机械主租户始终全功能，并让“外协监管”按委托方/接单方身份与委派关系权限显示和执行不同操作。

**实现方式：** 以 `lib/saas-features.js` 为模块目录和 API 归属的权威来源；服务端输出目录和有效模块，套餐后台与主程序菜单消费同一份数据。服务端在模块、用户岗位、租户关系及逐项委派权限各层分别授权。先复现套餐页错误请求，再根据真实状态码修复，不根据截图猜测根因。

**技术栈：** Node.js、原生 `node:test`、MySQL SaaS store、静态 HTML/JavaScript。

---

## 用户验收关注点

1. 套餐创建/编辑可选择完整主菜单模块，保存并刷新后准确回读。
2. 主程序主导航与套餐显示名称、模块键一致；API 未授权时返回 403。
3. `future-machinery` 无论套餐和覆盖如何配置，始终拥有当前完整业务功能。
4. 外协监管中主租户能建/撤委派、发任务并看本方委派进度；外协租户只能查看和处理指派给自己的任务，且受委派关系权限控制。
5. 不回归现有角色权限，不改原始 BOBO 功能基线及任何业务数据。

- [ ] 以关系授权清单 `tasks`、`progress`、`exceptions`、`attachments`、`quality`、`delivery` 为服务端判定依据，逐项核对当前任务状态动作、异常投影、附件、质检和交付 API；未授权操作返回 403，不能只隐藏按钮。
- [ ] 修复伙伴任务加载时关系权限未随伙伴侧查询读取的问题；按当前有效关系过滤任务及可见字段，撤销/过期关系不得继续提供操作权限。

**验收：** 主/伙伴角色的 API 与 UI 行为均符合关系权限；跨租户任务 ID 猜测无数据泄露；截图二所示紧凑工序流程可读，权限不足时不泄露对应信息。

## 风险与保护措施

- **存量套餐兼容：** 稳定键不改名、不重置套餐；增加迁移前后读取测试。
- **未来机械全功能回归：** 在权限解析/菜单渲染/API 守卫三个层面各有用例，固定完整模块集合。
- **关系权限被仅当 UI 控制：** API 服务端检查为强制层，UI 只反映授权结果。
- **旧服务/静态资源误诊：** 先记录本地真实请求与版本，再决定修复点；不在生产环境验证。
- **基线含未提交文件：** 只读基线，不用整目录复制、覆盖或清理方式同步。
- **范围与验证边界：** 不做生产数据库写入、线上部署、支付计费或小程序发布；无法在隔离环境验证的部分明确标记。
