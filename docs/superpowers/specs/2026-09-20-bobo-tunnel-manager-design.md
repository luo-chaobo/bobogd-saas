# 波波本地联调隧道管理设计

## 目标

用一套可重复执行的一键脚本替代手工输入 `ssh -R`。脚本必须保证本机只运行一个波波联调隧道，能够识别服务器 `127.0.0.1:13000` 上的有效隧道、项目遗留隧道和未知占用，并在断线后自动恢复，同时不得误杀其他 SSH 会话或服务器程序。

## 已确认的根因

- 当前联调依赖手工启动 SSH 反向隧道，没有唯一实例控制。
- 本机当前没有 `ssh` 隧道进程，但服务器仍拒绝绑定 `13000`，说明冲突位于服务器端或来自另一条连接。
- 现有命令的 `ServerAliveInterval` 只能帮助客户端发现连接异常，不能识别端口所有权，也不能安全处理服务器残留监听。
- 当前 Windows `ssh-agent` 服务处于禁用状态，密钥未载入；继续使用多条独立 SSH 命令会重复询问密钥口令。

## 使用方式

用户只需要运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\波波本地联调\启动联调.ps1"
```

停止时运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\波波本地联调\停止联调.ps1"
```

启动窗口保持打开，用于显示本地服务、隧道状态和重连信息。

## 组件

### `配置联调密钥.ps1`

一次性配置 Windows OpenSSH Authentication Agent：

1. 检查 `ssh-agent` 服务。
2. 服务被禁用时给出管理员执行命令，不静默提权。
3. 启动服务。
4. 调用 `ssh-add` 加载 `%USERPROFILE%\.ssh\wljixie_local_bobo_tunnel`。
5. 只显示指纹，不输出私钥或口令。

密钥保留口令。口令只由 `ssh-add` 的交互提示读取，不写入文件、命令行参数或日志。

### `启动联调.ps1`

负责完整生命周期：

1. 使用 Windows 命名互斥锁 `Local\WljixieBoboTunnel13000` 保证单实例。
2. 检查本机 `127.0.0.1:3000` 的健康接口。
3. 本地波波未运行时，从脚本所在目录启动 `server.js`，并记录本次创建的 Node 进程 PID。
4. 验证 SSH Agent 已加载指定密钥；未加载时停止并提示运行配置脚本。
5. 通过独立 SSH 控制连接检查服务器 `127.0.0.1:13000`。
6. 根据端口状态执行安全分支。
7. 启动受管理的反向隧道并监控子进程。
8. 子进程异常退出时采用有限退避自动重连。
9. 用户按 `Ctrl+C` 或关闭窗口时终止本脚本创建的隧道，并清理状态文件。

脚本不得结束启动前已经存在的本地 Node 服务。只有脚本本次创建的 Node 进程才允许在显式停止参数下结束。

### `停止联调.ps1`

只读取项目状态文件中记录的 PID，并在停止前验证：

- 进程仍然存在。
- 进程可执行文件是 `ssh.exe`。
- 命令行包含指定密钥、服务器地址和 `127.0.0.1:13000:127.0.0.1:3000`。

验证失败时拒绝结束进程。成功停止后通过远端检查确认端口释放，并删除状态文件。

### 状态文件

状态保存在 Git 忽略的 `tmp/tunnel-state.json`：

```json
{
  "sshPid": 1234,
  "nodePid": 5678,
  "startedAt": "2026-09-20T19:00:00+08:00",
  "remoteHost": "47.99.105.37",
  "remotePort": 13000,
  "localPort": 3000
}
```

状态文件不是进程所有权的唯一依据；停止前必须重新验证真实进程信息。

## 远端端口所有权

新的受管理隧道不再使用纯 `-N`。SSH 会话在服务器运行一个最小生命周期命令：

1. 将远端会话 PID 和固定标识写入 `/run/wljixie-bobo-tunnel-13000.state`。
2. 注册退出清理逻辑。
3. 保持会话运行。
4. 会话退出时删除状态文件。

启动脚本将服务器端口分为三类：

### 端口未占用

直接建立新隧道。

### 端口已提供正确健康响应

判定已有可用隧道。脚本显示“联调隧道已可用”，不再创建第二条隧道，也不结束任何进程。

### 端口占用但健康检查失败

- 若远端状态文件存在、PID 存活且命令标识完全匹配，则判定为本项目遗留会话，可以结束该会话后重建。
- 若状态文件缺失、PID 不存在、标识不匹配或监听程序不是预期 SSH 会话，则判定为未知占用。脚本打印诊断信息并停止，不自动执行 `fuser -k`、`pkill` 或其他广泛终止命令。

当前由旧手工命令产生的无标识占用属于一次性迁移问题。首次切换时需要人工查看服务器监听进程并明确确认后清理，不能由新脚本猜测删除。

## SSH 参数

受管理隧道固定使用：

```text
-T
-o BatchMode=yes
-o IdentitiesOnly=yes
-o ExitOnForwardFailure=yes
-o ServerAliveInterval=30
-o ServerAliveCountMax=3
-o TCPKeepAlive=yes
-R 127.0.0.1:13000:127.0.0.1:3000
```

`BatchMode=yes` 保证后台监控不会卡在口令提示；因此启动前必须完成 SSH Agent 配置。

## 自动重连

- 隧道运行超过 60 秒后退出，重连等待恢复为 2 秒。
- 连续快速失败时按 2、5、10、20、30 秒退避。
- 连续失败 10 次后停止自动重连，显示最后错误和手工诊断命令。
- 每次重连前重新检查本地健康接口和远端端口所有权。
- 本地波波不健康时暂停重连，避免建立指向空端口的隧道。

## 服务器 SSH 设置

服务器需设置失效连接检测：

```text
ClientAliveInterval 30
ClientAliveCountMax 3
```

修改前备份 SSH 配置，使用 `sshd -t` 验证后只重载服务，不直接重启。现有 SSH 会话保持开启，直到新连接验证成功。远端端口继续绑定 `127.0.0.1`，不得开放到公网地址。

## 日志与安全

- 日志写入 `logs/tunnel-manager.log`，不记录密钥、口令或环境变量内容。
- 日志记录启动、端口分类、PID、重连次数、健康检查结果和停止原因。
- 远端命令使用固定常量，不拼接用户输入。
- 服务器地址、端口和密钥路径集中定义在脚本头部，不从不可信文件读取。
- 任何未知端口占用都采用拒绝操作，不采用强制清理。

## 测试

自动化测试通过可注入的命令执行器模拟系统命令，覆盖：

1. 第二个启动实例被互斥锁拒绝。
2. 本地健康时不重复启动 Node。
3. 本地未启动时创建 Node 并记录 PID。
4. 正确健康响应使脚本复用已有隧道。
5. 有效远端状态标识允许清理遗留会话。
6. 未知监听程序被拒绝且不会调用终止命令。
7. SSH Agent 未加载密钥时给出明确提示。
8. SSH 子进程异常退出后按上限重连。
9. 停止脚本拒绝错误 PID 和不匹配命令行。
10. 日志不包含私钥路径以外的敏感内容。

人工验收覆盖：

1. 连续运行两次启动脚本不会出现 `remote port forwarding failed`。
2. 断网后恢复能够重连。
3. 强制结束受管理 SSH 进程后能够重连。
4. 服务器健康检查返回本地波波服务。
5. 关闭启动窗口后远端 `13000` 在存活检测周期内释放。

## 实施顺序

1. 编写纯函数和自动化测试，用于进程校验、端口分类和退避计算。
2. 实现一次性 SSH Agent 配置脚本。
3. 实现启动和停止脚本。
4. 在不连接正式服务器的模拟环境运行测试。
5. 人工登录服务器识别并清理当前旧占用。
6. 备份并验证服务器 SSH 存活设置。
7. 建立第一条受管理隧道并验证测试域名联调。

## 验收标准

- 日常联调只需运行一个启动脚本。
- 重复启动不会争抢 `13000`。
- 项目只能自动结束有完整所有权证据的隧道。
- 未知占用不会被自动终止。
- 网络中断能够有限次数自动恢复。
- 密钥口令不落盘、不出现在日志中。
- 本地波波数据和服务器业务数据不因隧道管理发生任何修改。
