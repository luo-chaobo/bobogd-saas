# BOBO SaaS 商业化实施路线

## 目标

基于本目录的 BOBO 源码副本，构建统一 SaaS 多租户产品。平台方管理公司及年费授权；主公司可委派订单/工序给独立外协租户，并查看被授权范围内的生产状态。

## 已确定的产品决策

- 统一 SaaS，按公司年费授权。
- 平台后台创建公司；首期不开放自助注册和在线支付。
- 指定二级工厂可设为 0 元授权。
- 外协单位使用独立公司空间；主公司通过明确委派关系监管任务。
- 到期后阻止新增业务操作，保留历史查询、导出和数据取回。
- 原仓库与文件保持只读，商业化修改只在本目录内进行。

## 业务模块

1. 租户身份、公司成员、会话和公司内角色。
2. 平台公司目录、管理员管理、年费授权及审计。
3. 主公司与外协公司的委派关系及撤销。
4. 外协任务接收、排产、报工、质检、异常及附件。
5. 主公司跨租户监管视图和验收。
6. 网站订单同步、进度回传、幂等重试和失败队列。
7. 租户数据迁移、备份恢复、用量与运营监控。

## 数据隔离与主程序功能完整性硬性要求（2026-10-18）

### 数据安全边界

- 宁波未来机械现有生产主程序及其 MySQL `app_state.main` 保持独立、原样运行；SaaS 开发、迁移、初始化和试运行不得连接或写入该生产库。
- SaaS 验收和上线前，为平台目录/会话/授权数据与每家公司的业务数据分库；每个租户使用独立 MySQL 数据库（或经安全评审确认等价隔离的独立实例）及仅有本租户权限的数据库账号。未来机械也使用自己的 SaaS 租户库，不与原生产库共用。
- 未来机械业务数据只能在备份核验后，从经确认的生产快照迁入其独立 SaaS 租户库；迁移不得改变原库。迁移前后核对客户、订单、工单、工序、报工、异常、附件元数据及审计记录数量和关键字段，并完成恢复演练。
- 服务端只依据已验证的会话，将请求路由到服务端登记的租户库和文件目录；客户端传入的租户 ID、公司标识或请求头不得决定数据库路由。缺少、失效或不匹配的租户上下文必须拒绝请求，不得回退到 `main`、默认租户或其他公司的数据。
- 平台后台只访问平台目录和经授权的监管数据；跨租户监管必须通过有范围、可审计的委派关系读取，不给予平台或普通租户任意访问业务库的通用账号。
- 数据库凭据放在部署密钥管理中，不入库、不写入前端；附件按租户隔离存储，下载、预览、搜索、导出和删除都需重新校验租户归属及委派权限。
- 上线前必须通过跨租户读写、伪造租户参数、会话串租、附件直链、搜索/导出越权、备份恢复和故障时拒绝访问等隔离验收。未通过不得接入未来机械生产数据。

### 宁波未来机械主程序功能完整性

- SaaS 版本必须保留未来机械当前生产主程序已有的后台 Web、微信小程序和电视看板功能；多租户改造不能以删页、隐藏入口或降低权限的方式规避兼容工作。任何确需改变的功能须先列明差异并由用户确认。

- 功能清单至少覆盖：登录与角色权限、员工及岗位设置、客户资料、订单和工单、工艺路线与派工、手机任务及扫码报工、质检与返工、异常闭环、图纸/附件、生产总览与电视/移动看板、历史查询、报表和导出、客户反馈、操作日志、基础设置、交付状态，以及现有系统间同步接口。
- 验收采用角色和端到端业务流程对照：老板/主管/管理员、办公室、车间岗位和质检角色分别验证 Web 与小程序可见范围及操作；从创建订单、派工、报工、异常/质检到完工交付，核对数量、状态、附件、审计与看板一致。对照基线不得出现未说明的功能缺失或回归。

## 2026-10-19 新租户数据库预配实现记录

- 平台后台创建新公司时，服务端按随机租户 ID 新建专属 MySQL 数据库和独立最小权限应用账号，创建空白 `app_state`，然后原子写入平台目录的公司、授权、账号和路由元数据。
- 租户应用密码由外部保存的 `SAAS_TENANT_CREDENTIAL_SECRET` 按租户 ID 派生；平台目录只保存非秘密路由元数据。应用使用的预配管理员账号只负责 DDL 和 GRANT，不能用于租户业务查询。
- 服务重启后从平台目录恢复已登记的租户路由；开户中途失败时尝试回收新数据库和账号。线上各实例必须使用同一个派生密钥并访问同一目录库。
- 代码路径已实现，尚未在用户本地 MySQL 实例验证开户、失败回滚、重启登录、多租户隔离和预配账号权限；上线仍需验证密钥管理、专用预配账号权限及跨租户安全门槛。

## 2026-10-18 本地实施记录

- 仅修改 `bobo-saas-commercial` 独立副本；用户指定同步小程序目录只读。副本无 Git 元数据，不能提供 Git diff 或确认其精确代码基线。
- 平台目录使用独立连接配置，业务数据按服务端租户 slug 路由到独立数据库；SaaS 状态固定使用各库的 `app_state.main`。平台 API 不先读取公司业务状态。缺映射/错误连接不回退共享 `main`。
- 本地 SQL 模板创建独立目录库/租户库及不同应用账号；启动凭据由 Windows DPAPI 保存。首次空白未来机械测试租户可初始化管理员和空白状态，不导入现有业务数据。
- 入站外部订单使用每租户唯一 HMAC 密钥反查目标租户，不接受请求方选库；进度、发货和配送完成事件按每租户 HTTPS 密钥发送并退避重试。
- 租户 API 与附件引用读取、平台管理员重置租户密码、租户引导及委外伙伴数据访问通过每租户 MySQL 命名锁串行化，避免整体 JSON 状态行并发覆盖。
- 当前 API 路径集合与只读主程序静态对照未发现源版缺失路径；路径存在不代表权限、数据行为或平台实际联调已验收。服务器本轮只做 `node --check`，此前 76 项测试结果早于本轮外部 API 和锁变更。
- 未连接生产数据库、未迁移数据、未部署或发布小程序。详见 `docs/feature-parity-inventory.md`。全功能、安全和迁移门槛未通过。
