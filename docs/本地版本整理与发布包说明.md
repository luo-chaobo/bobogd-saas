# 波波工单本地版本整理与发布包

本文用于把本地联调代码整理成可追踪的版本和纯代码包。它不连接服务器、不上传文件、不重启服务，也不读写线上数据库。旧线上副本 `D:\codex内容\copy黑湖小工单` 继续冻结，不从中复制订单数据、附件或配置。

## 日常版本更新顺序

1. 在本地波波主工作树完成修改，确认本次版本包含哪些功能；小程序有改动时，单独记录小程序仓库提交号。
2. 更新 `CHANGELOG.md` 的“未发布”内容，并按项目当前要求完成检查。报告测试结果时只写本次实际运行结果；历史测试结果不能代表后续提交。
3. 按版本策略更新 `package.json` 中的版本号。它与 Git 标签是两个独立字段，应在汇报中分别列出；例如现有 `bobo-v0.3.0-platform-integration` 标签中的代码包 `package.json` 版本是 `0.2.0`，不能把两者混为一谈。
4. 提交所有本版本代码和文档。创建符合 `bobo-v<major>.<minor>.<patch>-<feature>` 格式的新标签，标签只指向已经提交并完成所需检查的版本提交。不要移动或复用旧标签。
5. 在仓库根目录运行发布包脚本：

   ```powershell
   .\scripts\build-release.ps1 -Tag "bobo-v0.4.0-example"
   ```

   将示例标签替换成刚创建的真实标签。脚本要求当前 Git 工作区干净、标签存在且格式正确；已有同名产物时会停止，不覆盖旧包。
6. 查看 `release-output\<标签>\release-manifest.json` 和 SHA-256 文件。清单记录标签、完整提交号、包内 `package.json` 版本、构建时间、构建机器、文件清单和 ZIP 的 SHA-256。包内文件清单逐文件带有大小与 SHA-256。

   ```powershell
   Get-Content ".\release-output\<标签>\release-manifest.json"
   Get-FileHash ".\release-output\<标签>\<标签>.zip" -Algorithm SHA256
   ```

脚本只从指定 Git 标签导出受版本控制的文件，不压缩工作目录。它会拒绝数据库、附件、配置密钥、日志、缓存、依赖和备份路径；最终 ZIP 文件清单还会与 Git 导出的文件清单核对。发布产物保存在被 Git 忽略的 `release-output` 文件夹，不会进入下一次提交。

## 线上更新边界

生成并校验代码包不等于已部署。此流程不包含测试域名或正式域名上传，不执行宝塔、PM2、SSH 或数据库操作。线上实际目录、进程和数据备份/回滚流程核实完成前，不应把此代码包直接覆盖到线上目录。后续线上部署须另行确认目标环境及部署步骤。

若尚未实际查看旧线上目录，不要写“旧线上副本未修改”，应写“未核查”。仅当确认本轮没有部署时，才写测试域名和正式域名“未部署”。安全发布脚本与备份/回滚机制分别报告，不把本地打包脚本描述为已具备服务器回滚能力。

## 版本更新汇报格式

每次按实际情况填入以下格式。没有小程序修改时写“无”；没有创建标签时写“尚未创建”；未运行完整测试时说明原因；没有核实旧线上副本时写“未核查”。

```text
已整理成 Git 新版本，未触碰旧线上副本，也未部署。

- 主仓库提交：<短提交号>
- 小程序提交：<短提交号或无>
- 版本标签：<标签>
- 完整串行测试：<通过数>/<总数> 通过，或未运行及原因
- 本地工作区：干净 / 尚有未提交修改
- 旧线上副本：未修改 / 状态及依据
- 测试域名和正式域名：未部署 / 实际部署版本

本版本包含：
- <功能变更>

安全发布脚本与备份/回滚机制：已实施 / 尚未实施；说明剩余操作。
```
